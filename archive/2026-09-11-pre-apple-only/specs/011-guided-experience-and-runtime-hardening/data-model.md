# Data Model: Guided Experience And Runtime Hardening

## 1. RuntimeAssetRequirement

- Purpose: Represent a required runtime file that must exist before compose startup.
- Fields:
  - `id` (string): stable key, e.g. `stack.shared_file`, `stack.project_file`.
  - `label` (string): user-facing check label.
  - `path` (string): absolute required file path.
  - `requiredFor` (enum): `up|attach|down|shared-gateway`.
- Validation:
  - `path` must be non-empty absolute path.
  - file must exist and not be a directory.

## 2. RuntimePreflightResult

- Purpose: Aggregate runtime-asset preflight outcomes before lifecycle compose operations.
- Fields:
  - `requirements` ([]RuntimeAssetRequirement)
  - `missing` ([]RuntimeAssetRequirement)
  - `status` (enum): `ready|needs_action|error`.
  - `remedy` (string): StageServe-native next action text.
- Validation:
  - `status=ready` implies `missing` empty.
  - `status!=ready` implies non-empty `remedy`.

## 3. MachineReadinessSummary (extended usage)

- Purpose: Planner-facing readiness classification used by bare `stage` routing.
- Existing fields reused:
  - `checked`, `blocked`, `status`, `nextFixLabel`, `nextCommand`, `workItems`.
- Additional semantics:
  - Missing runtime assets are valid blockers in root guidance context.

## 4. LifecycleFailureEnvelope

- Purpose: Uniform operator-facing failure envelope for lifecycle failures.
- Fields:
  - `step` (string): failing lifecycle step.
  - `project` (string): affected slug or empty for shared infra.
  - `cause` (error/string): underlying failure.
  - `remedy` (string): required non-empty next action.
  - `partialEffects` ([]string, optional): side effects that already occurred.
- Validation:
  - `step` non-empty.
  - `remedy` non-empty in touched paths.

## 5. RuntimeServiceSummary

- Purpose: Running-project service metadata for guided logs/restart actions.
- Fields:
  - `serviceName` (string)
  - `containerName` (string)
  - `status` (string)
  - `eligibleForLogs` (bool)
  - `eligibleForRestart` (bool)
- Validation:
  - `serviceName` required.
  - eligibility flags derive from runtime metadata availability and policy.

## 6. ServiceSelectionDecision

- Purpose: Deterministic action routing for service-scoped guided actions.
- Fields:
  - `action` (enum): `logs|restart`
  - `mode` (enum): `auto_single|prompt_multi|fallback_advanced`
  - `selectedService` (string, optional)
  - `reason` (string)
- Validation:
  - `auto_single` requires exactly one eligible service.
  - `prompt_multi` requires >1 eligible service.
  - `fallback_advanced` requires explicit reason.

## 7. ConfirmationSurfaceState

- Purpose: State model for elevated destructive confirmations.
- Fields:
  - `actionId` (string)
  - `title` (string)
  - `changes` ([]string)
  - `noChanges` ([]string)
  - `confirmLabel` (string)
  - `cancelLabel` (string)
  - `severity` (enum): `warning|destructive`
- Validation:
  - `changes` non-empty for mutating actions.
  - both labels non-empty.

## 8. AsyncLifecycleActionState

- Purpose: Track long-running guided lifecycle execution.
- Fields:
  - `actionId` (string)
  - `status` (enum): `idle|running|success|failed|cancelled`
  - `startedAt` (timestamp)
  - `progressMessage` (string)
  - `canCancel` (bool)
  - `resultSummary` (string)
- Validation:
  - `running` requires `startedAt`.
  - `cancelled` must preserve cancellation semantics and produce next safe step.

## Relationships

- `RuntimePreflightResult` aggregates `RuntimeAssetRequirement`.
- `MachineReadinessSummary` may include runtime-asset blockers derived from `RuntimePreflightResult`.
- `LifecycleFailureEnvelope` may include `partialEffects` generated by lifecycle orchestration state transitions.
- `RuntimeServiceSummary` feeds `ServiceSelectionDecision`.
- `ConfirmationSurfaceState` and `AsyncLifecycleActionState` are UI-state layers over existing lifecycle actions.

## State Transitions

1. Preflight:
   - `RuntimePreflightResult`: `ready` or `needs_action/error` before compose startup.
2. Lifecycle:
   - `AsyncLifecycleActionState`: `idle -> running -> success|failed|cancelled`.
3. Selection:
   - `ServiceSelectionDecision`: evaluate eligible services to route `logs/restart` as `auto_single`, `prompt_multi`, or `fallback_advanced`.
